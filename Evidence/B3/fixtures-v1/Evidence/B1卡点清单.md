## 卡点 ④ — mock 引擎跨进程无状态,CLI dag tick/run 无法续跑 develop 流程

- **实测**:`dag tick` 每轮新进程,mock 内存(模块级 dict)清空 → work_item 找不到 → reconcile 标回 todo → 下一轮重新 create item(每轮 id 恒为 1)→ 无限循环,develop 节点永不推进。
  manifest 文件里 work_item_id 反复重建不落盘。
- **代码锚点**:mock 引擎状态全在模块级 `_shared_*`(mock.py),进程内共享;CLI 每次调用是独立进程。测试都是**同进程**反复 tick。
- **性质**:mock 引擎的 CLI 限制(非 content 卡点)。真引擎(multica)状态在平台 DB 无此问题(WEEK-8 即真引擎跑通)。
- **对 B1 的含义**:**CLI 路径的 mock 全链路测试不可行**,B1 方法需调整(同进程 python 驱动 / 或上真引擎)。
- **状态**:方法论已修正(仅"分次 dag tick"丢 mock 状态,dag run 单进程不丢);mocksite 测试场为 B3/B4 持续资产

## 重要修正(2026-08-19 补充实测:卡点④⑤根因修正 + 全链路跑通)

上述卡点④⑤的初判("mock 引擎限制"/"CLI 不可行")**不成立**,根因更精确:

- **卡点④修正**:`dag run` 是**单进程内部循环 tick**,mock 内存状态在同一次 run 内不丢;只有"分次调用 dag tick"才跨进程丢状态。CLI 全链路可行性不受影响。
- **卡点⑤根因修正**:merge 命令解析(`config.py resolve_merge_command`)读 **config.yaml 的 `engine` 键**,CLI `--engine mock` 覆盖**不传导**。learnezvibe/.omac/config.yaml 是 `engine: multica` -> mock 跑却执行真 `gh pr merge <假URL>` -> 必失败 -> 节点 blocked。测试能过是靠 autouse fixture patch 掉 gh 命令。
  - 验证:python 直跑 tick 传 `config={'engine':'mock'}` -> develop 节点立即收敛(done=['a'])。

### B1 目标实际达成:mock 全链路收敛现场

- **方法**:建隔离测试场 `learnezvibe/mocksite/`(自有 `.omac/config.yaml` 声明 `engine: mock`,worker=alice/reviewer=bob,engine_extra 里 MOCK_AUTO_COMPLETE_DELAY=0),不碰受保护的 learnezvibe/.omac 现场。
- **命令**:`omac dag run mocksite/manifest.yaml`(manifest = weekly 三节点 + pr_base: main 占位)
- **结果**:
```
dispatch collect -> node_done(id=1)
dispatch write   -> node_done(id=2)
dispatch review  -> review_dispatch(reviewer=bob) -> verdict=pass -> node_done(id=3)
converged done=3 total=3
collect done / write done / review done
```
- **意义**:①weekly 三节点(含评审节点)在 mock 下全链路收敛,评审机制(reviewer/bob verdict=pass)正常工作;②全链路通过也再次证明卡点②:content 语义的节点靠 mock 假 pr_url 假过了证据门(B2 必须修);③mocksite 模式可作为 B2 的回归测试场。
