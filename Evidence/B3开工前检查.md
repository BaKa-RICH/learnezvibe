### 指标源码口径

Multica 源码提供了可复算的 token 基础：

- `server/pkg/db/queries/task_usage.sql::GetIssueUsageSummary` 对一个 issue 下的 `task_usage` 分别汇总 `total_input_tokens`、`total_output_tokens`、`total_cache_read_tokens`、`total_cache_write_tokens`。
- 同一查询返回四类 `uncosted_*`，其过滤条件是 `cost_usd_ticks IS NULL`；这些值是对应 `total_*` 的子集。
- `packages/views/runtimes/utils.ts` 的 tokens total 同样计算为 input + output + cache read + cache write。
- 因此 B3 headline 明确定义为：

```text
total_tokens = total_input_tokens
             + total_output_tokens
             + total_cache_read_tokens
             + total_cache_write_tokens
```

`uncosted_input_tokens`、`uncosted_output_tokens`、`uncosted_cache_read_tokens`、`uncosted_cache_write_tokens` 单列披露，绝不再次加进 headline。由于 issue summary 按单个 issue 聚合，正式样本还必须枚举根 issue 及全部子 issue，并按唯一 issue/task id 去重后形成样本总值。

## 硬阻塞

以下任一项未关闭，都禁止创建 B3 正式样本：

### 1. 真实 content submit 参数合同仍是 PR 形态

`src/omac/pipeline/dispatch.py` 当前把 `TaskKind.DEVELOP x TaskPhase.AUTHORING` 固定映射为 `--pr-url + --verification-file`；`build_show_output()` 生成的 submit 模板沿用同一映射。`src/omac/cli/commands/work.py` 的用户帮助也明确写着 develop 产出为这两个参数。

影响：真实 content agent 即使生成 `weekly-data.md`，也没有符合当前 CLI 合同的无 PR 提交方式。B2 只改了 lint/evidence/loop/mock 策略，未打通真实 authoring submit。

关闭条件：TDD 增加 content authoring 参数与校验；`work show` 和 `work submit` 同源生成正确命令；PR 模式保持向后兼容；错误包含缺失项、修复方式和可复制命令。

### 2. Deliverable 未在真实提交中持久化，独立 workdir 无法读取

当前真实 develop submit 只保存 `artifacts={pr_url, head_sha?}` 与 verification。`WorkItemStore.update_work_item_metadata()` 已有 `deliverable` 抽象，Multica adapter 也有 deliverable/ref 读取路径，但 develop content submit 没有把文件字节写入该通道。下游 `omac work read` 最终读取 `upstream.deliverable`；不同 agent run 使用独立 workdir，不能依赖上游文件自然存在。

影响：`collect -> write` 和 `write -> review` 会在真实 Multica 链路断开；mock 的 `artifact_paths` 只是路径元数据，不能证明真实文件传输。

关闭条件：content submit 把交付文件作为平台 payload/ref 持久化并记录 SHA-256；下游通过 source ref 在独立 workdir 读回相同字节；测试覆盖缺失、篡改、错误摘要和 PR 回归。

### 3. 非计量 Desktop smoke 尚未成功

虽然三个 Desktop runtime online，且旧取消 workdir 可调用 OMAC 1.0.0，但新的 smoke issue 没有创建成功。现阶段没有证据证明 Desktop daemon 派出的新 agent 会完成目标 repo checkout、固定 revision 校验和真实跨节点读取。

关闭条件：先完成阻塞 1/2 与测试，再执行一个明确排除于样本的 smoke；四项断言全部通过且 CLI daemon 保持 stopped。smoke 未过不得以“先跑一个正式样本看看”替代。
