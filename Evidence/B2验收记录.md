## 实现清单(全部路由 core/delivery.py 单一策略模块)

| 差异点 | 锚点 | content 行为 |
|---|---|---|
| Contract 字段 | manifest.py | `delivery_mode: pr\|content`,缺省 None=pr;load/dump 兼容(旧 manifest 序列化零变化) |
| lint pr_base | lint.py `_contract_errors` | 仅 pr 模式必填;非法值报错不静默回落 |
| evidence pr_url | evidence.py `validate_worker_evidence` | 仅 pr 模式必填;content 验收由 verification_commands + integration_gates 通道承载 |
| merge 收口 | loop.py `_complete_merge_if_confirmed` | content 分支直达 done(不执行 sealed-delivery 校验/merge 命令) |
| PR 封印 | loop.py `_observe_worker_handoff` | content 走既有 complete-unsealed 通路(免交付身份封印) |
| done 终态 | loop.py `_reconcile_candidate` | content done 即终态(跳过 PR 远端合入观察,不再被打回 blocked) |
| 评审基线 | loop.py `_review_cutoff_created_at`(新) | content 以 verification 附件上传时间为评审因果基线(替代封印身份时间) |
| mock 交付 | mock.py auto-complete | content 产物型 artifacts(artifact_paths=source_of_truth),不再伪造 pr_url(消灭 B1 卡点②的 mock 假过) |

## 计划外发现(B1 清单未预判,B2 实测补录)

1. **差异点比 B1 预判多 4 处**:merge 收口之外,还有 PR 封印(complete-unsealed)、done 终态 reconcile、评审因果基线三处 PR 专属机制,content 都需要分叉--全部路由到 delivery.py,未散写 if。
2. **评审机制在 content 下可用**:reviewer 基线从"封印身份时间"换成"verification 附件时间"后,bob 的评审全链路(pass verdict)正常工作--B4"content 形态下 reviewer/返工/收口行为"提前拿到正向信号。
